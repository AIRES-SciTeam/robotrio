# MissionController

Новая версия контроллера из `flight` использует блоки `app` и готовый `MissionEnv`.
Окружение передаётся целиком: контроллер не создаёт и не останавливает Commander,
камеру или захват. Зависимости камеры и Gazebo не импортируются для аннотаций
`MissionEnv`, поэтому миссии без зрения можно запускать без ROS.

```python
from mission.mission_controller import (
    MissionController, MissionStep, MissionState, FailureAction,
)
from mission.mission_block import Arm, MoveTo, Hold, Land, Disarm

# env — MissionEnv с Commander, logger и нужными устройствами.
mission = MissionController(
    mission_env=env,
    tick_period=0.1,
    plan=[
        MissionStep(Arm, on_failure=FailureAction.RETRY, max_retries=2),
        MissionStep(MoveTo, {"pos": (0, 0, -1)}),
        MissionStep(MoveTo, {"pos": (2, 0, -1)}),
    ],
    pause_steps=[MissionStep(Hold)],
    end_steps=[MissionStep(Land), MissionStep(Disarm)],
    fail_steps=[MissionStep(Land)],
)
mission.start()

# Вызываются обработчиками команд оператора:
mission.pause()
mission.switch_to(2)  # индексы с нуля; на паузе выбирает следующий блок
mission.resume()
mission.skip()        # отменяет текущий основной блок и переходит к следующему
```

## Управление

- `start()` запускает фоновый поток один раз. Для следующего запуска создайте новый
  контроллер. `start(background=False)` позволяет вызывать `tick()` самостоятельно.
- `pause()` отменяет текущий основной блок и запускает `pause_steps`.
  `resume()` отменяет блок паузы и создаёт основной блок заново. Его локальные
  таймеры, состояние и бюджет повторов сбрасываются. Уже выполненные физические
  действия (например, захват груза) не откатываются.
- `toggle()` переключает паузу и выполнение.
- `switch_to(index)` отменяет текущий основной блок и выбирает указанный; переход
  к тому же индексу перезапускает блок. Неверный индекс вызывает `IndexError`.
- `skip()` / `next()` пропускает один основной блок; `prev()` выбирает предыдущий.
  На первом блоке `prev()` ничего не делает. Пропуск последнего ведёт к окончанию.
- На паузе переходы меняют только выбранный индекс основного плана. Цепочка паузы
  продолжает выполняться до `resume()`. Пропуск последнего блока на паузе также
  ждёт `resume()` перед выполнением окончания.
- `finish()` досрочно завершает основной план и запускает `end_steps`.
- `stop()` отменяет текущий блок, останавливает поток и выставляет `STOPPED`.
  Цепочки окончания и ошибки при этом **не запускаются**. Уже достигнутые
  `COMPLETED` / `FAILED` сохраняются. Для штатной посадки используйте `finish()`
  с соответствующим `end_steps`, а не `stop()`.

Методы управления возвращают `True`, если команда принята, иначе `False`.
Переключения основного плана разрешены только в `RUNNING` и `PAUSED`.
Команды и `tick()` выполняются последовательно под блокировкой: команда ждёт
завершения текущего вызова блока. Длительность блокирующего `tick()` определяет
задержку реакции на команды. Ожидание между повторными попытками не блокирует их.
Не вызывайте ручной `tick()` одновременно с фоновым режимом.

## Цепочки и ошибки

`pause_steps`, `end_steps`, `fail_steps` — последовательности `MissionStep`;
по умолчанию пустые. Конечная цепочка паузы выполняется один раз, затем контроллер
остаётся на паузе. Для постоянной отправки команд используйте длительный блок,
например `Hold` без тайм-аута. `Hold` без `pos` отправляет нулевую скорость;
для удержания заданной позиции передайте `pos`. Пустая пауза не отправляет
команд дрону, а одна отмена блока не отменяет последнюю Offboard-цель.

Каждый шаг, включая вспомогательные цепочки, поддерживает:

- `FailureAction.FAIL` — перейти к цепочке ошибки (по умолчанию).
- `FailureAction.SKIP` — продолжить следующим шагом текущей цепочки.
- `FailureAction.RETRY` — создать новый экземпляр блока после `retry_delay`
  секунд. `max_retries` — число дополнительных попыток после первой.
  Бюджет сохраняется между тиками одной попытки; после исчерпания — ошибка.

Исключения конструктора, `start()` и `tick()`, а также возврат `FAILED` или
`CANCELLED` обрабатываются политикой шага. Ошибка цепочки окончания или паузы
запускает `fail_steps`. Необработанная ошибка внутри `fail_steps` немедленно
завершает миссию как `FAILED`, без рекурсивного повторения обработчика.
Во время `retry_delay` контроллер не выполняет блок удержания и не обновляет
Offboard-цели; выбирайте задержку с учётом тайм-аута Commander.

Состояния: `IDLE → RUNNING → FINISHING → COMPLETED`; при ошибке —
`FAILING → FAILED`; при паузе — `PAUSED`. В `FINISHING` и `FAILING` вспомогательные
блоки ещё выполняются. Следить за результатом можно через `state`,
`current_index`, `current_block` и `last_error` (последняя ошибка, в том числе
восстановленная повтором). Экземпляры из `current_block` предназначены только
для наблюдения; управлять ими следует через контроллер.

## Наведение над тегом

```python
from mission.mission_block import MoveAboveTag

step = MissionStep(MoveAboveTag, {
    "tag_id": 7,
    "tag_size": 0.20,  # сторона тега в метрах для оценки позы
    "height": 1.0,     # вертикально над центром тега, не над началом NED
})
```

До первого обнаружения блок удерживает исходную позицию и вращается по yaw
со скоростью `search_yaw_rate` (по умолчанию 0.3 рад/с, около 17°/с). После
обнаружения пересчитывает центр тега из optical через FRD в NED с учётом
смещения камеры и кватерниона дрона. При потере тега или отсутствии нового
кадра продолжает отправлять последнюю цель в NED и возобновляет вращение.
Повторный кадр считается устаревшим через `detection_timeout` (0.5 с).
Повторное обнаружение обновляет цель и фиксирует текущий курс, прекращая
вращение. Достижение цели с малой скоростью в течение `settle_time` при
актуальных обнаружениях завершает блок. Во время поиска блок не завершается
и не имеет тайм-аута. Параметры `eps`,
`speed_eps`, `settle_time` задают точность и время стабилизации.

Нужны калибровка и корректные `camera_rotation` (optical → FRD),
`camera_position` (в FRD) именно используемой камеры. Высота отсчитывается
по вертикали NED, а не по нормали наклонённого тега. Используется последняя
телеметрия, без интерполяции на время экспозиции: при задержке изображения
или быстром движении возможна ошибка цели. Блок не армит дрон и не меняет
план `main`; Offboard включается штатным `set_offboard_target`.
